# Historical task receipts

This directory preserves earlier implementation, verification, review, and unblock records. Receipts describe their named task, revision, and time; they are not a live task board or proof that the current study is complete.

For reader documentation, use the [documentation index](../README.md). For current research claims, use the [project README](../../README.md), [evidence ledger](../evidence-status.tsv), and [architectural execution plan](../architectural-drift-execution.md).

## Finding a record

- Task IDs such as `S06`, `C06`, and `D03` identify related implementation and verification records. Check each receipt's exact revision and cited evidence.
- `unblock-*`, `haunt-*`, and similar notices record historical coordination or reviews. A filename or earlier disposition does not establish present readiness.
- Date suffixes distinguish iterations. Preserve distinct source bindings and findings when consolidating reader summaries.

Keep these historical paths available for existing citations. Before moving or merging a receipt, check inbound links, preserve unique evidence, and update references. New resident wake notes, local requests, checks, plans, and handoffs go in `.mishe-tauftauf/`; this archive is not the destination for routine live coordination.
